# OpenAPI specs

Generated files — do not edit by hand. Each is committed so it can be reviewed
in a pull request diff and consumed without a running server; CI regenerates
them and fails if what you committed is stale.

| File                                 | Describes                               | Generated by                                          |
| ------------------------------------ | --------------------------------------- | ----------------------------------------------------- |
| [`auto-ontology-api.json`](./auto-ontology-api.json)     | **The public API.**                     | `pnpm openapi` (from `frontend/`)                     |
| [`backend.json`](./backend.json)     | Internal Auto Ontology FastAPI app.               | `uv run python -m dev_tools.generate_backend_openapi` |

## Which one do consumers want?

`auto-ontology-api.json`. The Python services are ClusterIP-only and reachable solely
through the Next.js proxy, so `backend.json` and `ingestion.json` describe an
internal surface nobody outside the cluster can call. They exist because
`auto-ontology-api.json` is built partly from them.

`auto-ontology-api.json` also carries things the FastAPI specs cannot know:

- `x-auto-ontology-permissions` — the permission a caller needs, read from each route's
  `withPermission({...})` wrapper (or `"public"` for `withPublic`), plus the
  401/403 responses that implies. The same wrapper decides each operation's
  `security`: the `ApiToken` scheme, or `[]` for a `withPublic` route.
- `x-auto-ontology-source` — the `route.ts` that serves the operation.
- `x-auto-ontology-proxied` — whether the handler forwards to FastAPI or answers itself.
- `x-auto-ontology-upstream` — for the chat routes, the backend path whose response is
  relayed.

## How it is built

`frontend/scripts/generate-openapi.ts` walks `frontend/app/api/**/route.ts` with
ts-morph — file-based routing makes the paths deterministic — and fills in
schemas from two sources:

- **Proxied handlers** (`proxyToBackend`) forward the pathname verbatim, so
  their schemas are merged from `backend.json` by matching path and method.
- **Everything else** — the Prisma-backed handlers, which have no FastAPI
  counterpart, and the chat handlers, which build their own upstream request —
  declares its shapes in a sibling `app/api/**/openapi.ts` module using zod.
  See `frontend/types/openapi.ts` for that contract. The declaration lives
  beside `route.ts` rather than inside it because a plain Node script cannot
  import a route handler (`next/headers`, `after()`, `getPrisma()`).

Only the component schemas the public spec actually references are copied over,
closed transitively.

## Regenerating

```sh
uv run python -m dev_tools.generate_backend_openapi   # backend.json, ingestion.json
cd frontend && pnpm openapi                           # auto-ontology-api.json
```

Run them in that order — the public spec reads the committed `backend.json`.

## Conventions

**The API is snake_case throughout** — path segments, path and query
parameters, request bodies and response fields. A new endpoint is expected to
follow that, whatever the naming of the code behind it:

- Dynamic route folders are named for the parameter they carry, in snake_case:
  `app/api/terms/[term_id]/route.ts` → `/api/terms/{term_id}`.
- The Prisma models behind the frontend-only routes use snake_case field names,
  so a row serialises straight to the API shape with no mapping layer.
- Where the code behind a route is camelCase and cannot change, the handler
  maps at the boundary rather than leaking it: the Better Auth models (`User`,
  `Session`, `Account`, `SsoProvider`) are generated camelCase, and
  `GET /api/sso-providers` publishes `provider_id`. `GET /api/sso-discovery`
  likewise relays the OpenID Connect Discovery document under its own
  standard names.
- Internal TypeScript keeps normal camelCase locals and UI types; only what
  crosses the wire is snake_case.

The generator enforces some of this: it refuses to publish a route whose
`withPermission(...)` argument it cannot read, and fails on any `route.ts`
that exports no HTTP method it recognises, so nothing is dropped silently.

## Known limitations

- No `servers` block yet: the spec says how to authenticate, but not against
  which host.
- Most schemas carry `additionalProperties: true`. Backend response models are
  deliberately permissive — FastAPI _drops_ undeclared fields when a
  `response_model` is set, so a strict model would silently break responses
  rather than merely document them. Listed fields are reliable; the list is not
  guaranteed exhaustive.
- `PATCH /api/nodes/{node_id}` returns `NodeUpdateResult | null`, whose fields
  are all optional: the body echoes only the properties the request patched.
  The route also accepts any of them for any node type — `sample_values` is
  meaningful on a Column but is not rejected on a Database.
- `/api/auth/{all}` is Better Auth's catch-all. It appears in the spec, but its
  per-endpoint request and response shapes are the library's and are not
  mirrored here.
